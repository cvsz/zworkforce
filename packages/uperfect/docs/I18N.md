# Dashboard i18n TH/EN / ระบบสองภาษาของ Dashboard

## ภาษาไทย

Dashboard ใช้ภาษาไทยเป็นค่าเริ่มต้นและสลับเป็น English ได้จากปุ่ม TH/EN
ภาษาเลือกจาก localStorage key `uperfect-language` หรือ `default_language` จาก
workspace settings เมื่อยังไม่มีค่าที่ผู้ใช้เลือกเอง

กติกา:

1. visible label ใหม่ต้องมีทั้ง TH และ EN
2. shared label ใช้ translation key ใน `web/app.js`
3. view-specific copy ใช้ `tx(th, en)`
4. API record ที่แสดงในหน้าใช้ `th`/`en` fields เมื่อมี
   โดย integration status ใช้ `label_th`/`label_en` และ `setup_note_th`/`setup_note_en`
5. product facts ที่ merchant ให้มาอาจคงชื่อสินค้าต้นฉบับได้ แต่คำอธิบาย UI ต้องแปล
6. เปลี่ยน shell ให้ bump version ใน `index.html`, `app.js`, และ service worker
7. ต้องตรวจ mobile และ desktop หลังสลับภาษา

ไม่ควรใช้ string concatenation ที่ทำให้คำไทย/อังกฤษปนกันในประโยคเดียว และต้อง
หลีกเลี่ยง label ที่ล้นปุ่มบนหน้าจอเล็ก

## English

The Dashboard defaults to Thai and switches to English through the TH/EN control.
The choice is stored under `uperfect-language`, falling back to workspace
`default_language` when the user has not selected a language.

Rules:

1. Every new visible label needs both TH and EN.
2. Use translation keys in `web/app.js` for shared labels.
3. Use `tx(th, en)` for view-specific copy.
4. Render bilingual API fields through the localizer.
   Integration status records use `label_th`/`label_en` and
   `setup_note_th`/`setup_note_en`.
5. Preserve merchant product names when necessary, but translate UI descriptions.
6. Bump `index.html`, `app.js`, and service-worker shell versions after shell changes.
7. Check both mobile and desktop after switching language.

Avoid mixed-language sentence concatenation and labels that overflow compact controls.

## Verification

```bash
node --check web/app.js
.venv/bin/python -m pytest -q tests/test_api.py
```

Browser checks should visit every view in TH and EN and confirm `html[lang]` plus
the visible view title and navigation label.
