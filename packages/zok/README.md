# Zok Conversational Commerce OS

Zok is a Vite/React dashboard with an Express API adapter for a conversational-commerce workspace. The current repository is a hardened developer/sandbox release. It is **not** a Gold Master: external channel delivery, durable multi-tenant storage, RBAC, billing, and the enterprise SLOs in `ZOK_COMPLETE_RELEASE_PLAN.md` still require separate implementation and evidence.

## Canonical Runtime

The supported runtime is:

```text
Browser -> Vite-built dist/ (or Caddy) -> Express API on 127.0.0.1:3005
```

`src/App.jsx` and `src/views/Dashboard/` are the canonical frontend. `server.js` provides the local API adapter backed by `server/db.json`. The old Next/HTML route artifacts remain in the tree for reference and are not part of `npm run build`.

## Implemented

- Unified Inbox, AI Agent Studio, Flow Builder, Broadcasts, Analytics, Integrations, and release-pillar views.
- Session login using an administrator email and PBKDF2 password hash from environment variables.
- HttpOnly session cookie, SameSite protection, CSRF token enforcement for mutations, origin allowlist, API rate limits, body-size limits, and security headers.
- Strict validation for chat messages, tags, AI configuration, flow nodes, campaigns, and integration identifiers.
- Sandbox integrations start disconnected and cannot claim connected status without a verified provider record.
- Atomic serialized JSON mutations that refuse to overwrite a corrupt database file.
- Public `/api/health` endpoint and Node integration tests for the authenticated request path.

The channel cards and AI simulator are local UI/data simulations. They do not send messages to LINE, WhatsApp, Meta, TikTok, Shopee, Lazada, Shopify, or HubSpot.

## Quick Start

Requirements: Node.js 22+ and npm.

```bash
cd /mnt/zok
cp .env.example .env
node scripts/hash-password.mjs "replace-with-a-password-at-least-12-chars"
```

Put the generated hash in `ZOK_ADMIN_PASSWORD_HASH` in `.env`, set a real `ZOK_ADMIN_EMAIL`, then run:

```bash
npm ci
npm test
npm run lint
npm run typecheck
npm run build
npm run dev
```

Development URLs:

- Frontend: `http://127.0.0.1:5175`
- API health: `http://127.0.0.1:3005/api/health`

The API deliberately returns `503 Authentication is not configured` for protected routes until the administrator credentials are configured. Do not add credentials to source code.

## Environment

Copy `.env.example` to `.env`. The important variables are:

| Variable | Purpose |
| --- | --- |
| `NODE_ENV` | Set to `production` behind HTTPS so session cookies use `Secure`. |
| `PORT` | Express API port; default `3005`. |
| `ZOK_DB_FILE` | Local JSON adapter path; default `./server/db.json`. |
| `ZOK_ALLOWED_ORIGINS` | Comma-separated browser origins allowed to call the API. |
| `ZOK_SESSION_TTL_MS` | Session lifetime in milliseconds. |
| `ZOK_ADMIN_EMAIL` | Provisioned administrator email. |
| `ZOK_ADMIN_PASSWORD_HASH` | PBKDF2 hash generated by `scripts/hash-password.mjs`. |

`.env`, `server/db.json`, `node_modules`, `.venv`, and build output are ignored. `server/db.json` is local mutable demo state and must not be treated as a production database.

## Production-Shaped Local Deployment

Build the static client and run the API separately:

```bash
npm ci
npm run test
npm run build
NODE_ENV=production npm start
```

For a real deployment, serve `dist/` from Caddy or another TLS reverse proxy and proxy `/api/*` to `127.0.0.1:3005`. Do not expose the Express port directly. The JSON adapter is single-process only; PostgreSQL/Redis, distributed sessions, migrations, backups, queue workers, and observability are prerequisites for horizontal scaling.

## Release Gates

The exact release matrix is maintained in `ZOK_COMPLETE_RELEASE_PLAN.md`. At minimum, a change must pass:

```bash
npm ci
npm test
npm run lint
npm run typecheck
npm run build
npm audit --omit=dev --audit-level=high
```

Passing these commands proves build and local API hardening only. It does not prove external webhook delivery, PDPA/GDPR compliance, penetration testing, load targets, disaster recovery, or a 99.99% SLA.
